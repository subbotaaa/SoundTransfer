# SoundTransfer (`st`)

Передача **всего системного звука Windows → Mac** по локальной сети с минимальной задержкой.
Один бинарник на Rust: на Windows работает отправитель (захват WASAPI loopback), на Mac — приёмник (CoreAudio).

**Запуск без аргументов (двойной клик) открывает графический интерфейс** — вкладки
«Отправка»/«Приём», поле IP, слайдер джиттер-буфера, выбор устройства, живая статистика.
CLI-режимы (`st send` / `st recv`) остаются для скриптов и автозапуска.

- Windows: ярлык **SoundTransfer** на рабочем столе (или `st.exe` двойным кликом).
- Mac: `sh make_app.sh` собирает **SoundTransfer.app** — перетащите его в «Программы»
  и запускайте как обычное приложение.

```
Windows (игра) ──WASAPI loopback──> st send ──UDP/LAN──> st recv ──CoreAudio──> Mac → AirPods
```

## Ожидания по задержке (честно)

| Участок | Задержка |
|---|---|
| Захват + сеть + буфер + вывод на Mac (наша часть) | ~25–50 мс |
| Bluetooth до AirPods (вне нашего контроля) | ещё ~150–250 мс |

Для музыки, видео и казуальных игр — нормально. Для соревновательных шутеров
подключите к Mac **проводные** наушники: останется только наша часть.

## Сборка

### Windows (уже собрано)

```powershell
$env:CARGO_TARGET_DIR = "C:\Users\mirap\.cargo-target\soundtransfer"; cargo build --release
# бинарник: C:\Users\mirap\.cargo-target\soundtransfer\release\st.exe
```

(`CARGO_TARGET_DIR` выносит артефакты сборки из OneDrive, чтобы синхронизация не мешала.
В репозитории этот путь не хранится — он Windows-специфичный и ломал бы сборку на Mac.)

### Mac

Кросс-компиляция Windows→macOS непрактична, поэтому собираем на самом Mac (5 минут):

```bash
# 1. Rust (если ещё нет)
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
# 2. Линкер Xcode (если ещё нет)
xcode-select --install
# 3. Скопируйте папку проекта на Mac (git clone / AirDrop / общая папка) и:
cd SoundTransfer
cargo build --release
```

При первом запуске macOS спросит про входящие соединения — нажмите **Allow**.

## Использование

**На Mac (сначала запустить приёмник):**

```bash
./target/release/st recv
```

**На Windows (узнайте IP Mac: Системные настройки → Wi-Fi → Details):**

```powershell
st.exe send 192.168.1.XX
```

Всё. Звук игры/системы пойдёт на Mac. Остановка — Ctrl-C (отправитель шлёт BYE).

### Полезные опции

```text
st recv --buffer-ms 20      # целевой джиттер-буфер: меньше = ниже задержка,
                            # больше = устойчивее к Wi-Fi (диапазон разумного: 10–60)
st recv --device "AirPods"  # вывод в конкретное устройство (подстрока имени)
st send <ip> --format f32   # без 16-битного сжатия (3.2 Мбит/с вместо 1.6)
st send <ip> --frames-per-packet 256   # крупнее пакеты (терпимее к CPU, чуть больше задержка)
st list-devices             # показать устройства вывода
st send --dump out.raw --seconds 10    # диагностика захвата: запись в файл + peak/RMS
```

## Как это работает

- **Захват:** WASAPI loopback через cpal — устройство вывода открывается как вход,
  Windows отдаёт копию всего микса (48 кГц / f32 / стерео как правило).
  При тишине в системе loopback не выдаёт данных — отправитель это замечает
  и синтезирует пакеты тишины по wall-clock, чтобы приёмник не пересобирал буфер.
- **Транспорт:** UDP, сырой PCM s16le (~1.6 Мбит/с — кодек не нужен, нет его задержки).
  Пакет = 24-байтовый заголовок (magic, seq, sample_pos, формат) + 128 фреймов (2.67 мс).
- **Приёмник:** джиттер-буфер с целью 20 мс. Потерянные пакеты → тишина (тайминг
  сохраняется), поздние → drop, переполнение после Wi-Fi-затыка → срез до цели.
  Дрейф часов Windows/Mac компенсируется незаметным drop/dup одного фрейма
  на ~10 мс потока при уходе EMA заполненности за ±4 мс от цели.
- Раз в секунду приёмник печатает статистику: заполненность буфера, потери,
  underruns, срезы, slip. Если underruns регулярные — увеличьте `--buffer-ms`.

## Советы по сети

- Mac лучше держать на **5 ГГц** Wi-Fi; ПК — по кабелю (у вас уже так).
- Спайки >20 мс в `ping <mac-ip>` с ПК — причина щелчков; это Wi-Fi, не приложение.
- Порт по умолчанию **48100/UDP** (изменить: `--port` с обеих сторон).

## Замер задержки

Играйте клик-трек на ПК, положите телефон с диктофоном между колонками ПК и
колонками Mac, запишите, откройте запись в Audacity и измерьте смещение между
парами щелчков. С колонками Mac видно задержку приложения (~цель ≤60 мс),
с AirPods — полную, включая Bluetooth.

## Автообнаружение (mDNS)

Приёмник анонсирует себя в локальной сети (`_soundtransfer._udp`), поэтому IP можно не вводить:

- **GUI:** кнопка «🔍 Найти» рядом с полем IP — найденный Mac подставится сам.
- **CLI:** просто `st send` без адреса — найдёт приёмник за ~3 секунды.

Если поиск не находит Mac (редко: multicast отключён на роутере) — вводите IP вручную, как раньше.

## Управление из Home Assistant

Приложение (в GUI-режиме) поднимает HTTP-сервер управления на порту **48101**:

```text
POST /start   — запустить передачу (Windows) или приём (Mac)
POST /stop    — остановить
GET  /status  — {"running":true|false,"info":"..."}
```

Готовый конфиг переключателя — в [homeassistant.yaml](homeassistant.yaml): добавьте его
в `configuration.yaml` HA, поправьте IP при необходимости и перезапустите HA.
Появится переключатель **«Звук ПК → Mac»**: включение стартует приём на Mac и отправку
на ПК, выключение останавливает оба.

Чтобы кнопка работала всегда, приложение должно быть запущено на обеих машинах:

- **Windows:** ярлык в автозагрузке уже создан (`shell:startup`), правило брандмауэра
  для TCP 48101 добавлено.
- **Mac:** `sh make_app.sh --autostart` — соберёт приложение, положит в /Applications
  и настроит автозапуск при входе **в скрытом виде** (только иконка в строке меню,
  LaunchAgent `local.soundtransfer`). Если раньше добавляли приложение в «Объекты
  входа» — удалите оттуда, чтобы не запускалось дважды.

Флаг `--hidden` запускает GUI со скрытым окном (только трей/строка меню) на любой
платформе. Закрытие окна тоже прячет приложение в трей; полный выход — через
пункт «Выход» в меню трея.

Отправитель при старте из HA использует сохранённый IP приёмника, а если поле пустое —
находит Mac сам через mDNS. Сервер управления не имеет аутентификации — он рассчитан
на доверенную домашнюю сеть.
